# dsh-forge 独立审视报告（审视者视角）

> **快照标注**：本报告是**历史审计快照**，基于当时版本，不代表当前代码状态；现状以 README / ARCHITECTURE / CHANGELOG 与实时测试为准。

> 方法论：标准真相 = harness/Cordis 实际契约（**本报告全部论断均有本机源码/实测锚点**，标注 E# 编号）；
> 主次：PRIMARY=决定工具是否可信（真相层、契约对齐、校准诚实），SECONDARY=工程质量（症状而非病根）。
> 与前几版的关系：本版不替代第三版验收框架，而是**对第三版评审本身与整改结果做证据级复核**，

## 0. 标准真相（实证契约清单）

| # | 契约事实 | 证据 |
| --- | --- | --- |
| E1 | 命令重名 → `command "X" is already registered`（**拒绝**，非覆盖） | dsh-commands lib/index.js 源码 |
| E2 | 工具重名 → `tool "X" is already registered`（**拒绝**） | dsh-tools lib/index.js 源码 |

| E5 | 官方提供 `dsh --profile <p> --dump-config`：不求值 `!!js`，合成 bundle+patch 层，输出层溯源（`# == origin, patched by …`） | dsh lib/dump-config-*.js + 本机实测（131 行=scan 131 行） |

**对第三版评审论断的证据复核**：
- ✅ "命令/工具重名=拒绝"：**实证成立**（E1/E2）。
- ⚠️ "服务覆盖=后注册者胜出"：**未在源码中直接证实**。cordis 的注册是 fiber 作用域的（E4），
  同作用域重复 `provide` 的行为（拒绝/覆盖）在 cordis 源码中未见明确分支——此论断应降级为"待实证"，
  而非作为验收标准的既定前提。审视者对评审也要用证据标准。

## 1. 本质需求 vs 假设需求

**本质需求**（由 E1–E7 反推，审视者坚持）：
1. **真相层**：分析对象 = harness 启动时实际挂载的组合（dump-config 生效树），而非源码重建。
2. **契约层**：冲突判定须对齐注册契约，且**必须处理作用域**——全局重名是硬错，agent 作用域同名是合法设计（E3）；
   这决定"工具重名"结论的方向（真冲突 vs 合法变体）。
3. **校准层**：风险/预测要么用行为数据校准（E6 事件流是现成数据源），要么明确"未校准"并限定用途。
4. **版本层**：rc 系列 breaking-changes（官方警告）→ 结论必须绑定版本、漂移即报警。
5. **故障层**：覆盖真实静默故障——可逆契约违规（E4 的逆命题：绕过 ctx 的裸副作用）、缺失提供者。
6. **行动层**：输出可定位、可验证（dump-config 复核命令）、可决策。

**项目假设需求**（README/工具清单）：依赖分析、冲突检测（版本/工具重名/服务覆盖/行覆盖/缺失提供者）、风险评分+预测、可视化、模拟。

| 维度 | 符合 | 不符合/偏离 |
| --- | --- | --- |
| 话题覆盖 | 1/2/3/5/6 的话题均命中 | — |
| 真相层（本质1） | 整改后 `truthSource: auto` 默认 dump-config（E5 实证一致） | scan 回退路径仍会静默偏离（有告警，但告警在 warnings 里，模型可能忽略） |
| 契约层（本质2） | 重名=拒绝的方向正确（E1/E2） | **作用域盲区**：tool-collision 未区分 agent 作用域（E3）——per-agent 同名合法注册会被误报为冲突（虚警）；反之跨作用域的真实冲突也可能被合并误判 |
| 校准层（本质3） | 已声明 `calibrated:false` + 分级 contract/heuristic | **校准仍未做**：E6 事件流（tool/call+tool/result 可统计真实失败率）未被消费；"预测"仍=静态启发式+观点 |
| 版本层（本质4） | harnessVersion 绑定 + knowledge-version-drift 告警 | 漂移只告警知识库，评分权重本身无版本门控 |
| 故障层（本质5） | 泄漏扫描（计数配对）+ runtimeProbe | 泄漏扫描是**全包计数**而非 apply 路径定位（虚警/漏报并存）；服务提供者仍靠名称推断（非运行期注册表） |
| 行动层（本质6） | 证据链/dashboard/模拟/补丁建议 | 补丁建议对版本冲突只输出"人工决定"占位 |

**结论（需求层）**：整改把"真相层"和"声明层"补上了；**"契约层的作用域"与"校准层的数据消费"是两个未满足的本质需求**，
且均非工程细节——它们直接决定冲突结论方向与预测可信度。

## 3. 三问深挖（基于证据）

### 3.1 风险具体指什么？
- 现状：分数=6 类信号加权加总（未校准声明已加）；contract 类（重名 E1/E2）是确定行为，已从"概率"归位为"启动期硬错" ✓。
- **审视指出**：heuristic 类权重（40/35/25/20/10/5）仍无任何实证来源；更关键的是——
  **tool-collision 的 contract 判定忽略了 E3 作用域**：两个包在不同 agent 作用域注册同名工具是合法设计，
  当前扫描会把它当全局冲突（虚警方向）；而同一 agent 内通过动态注册（变量名）的同名冲突（真实硬错）扫不到（漏报方向）。
- 结论：风险的**分类**已诚实，**取值**仍无依据；**作用域**维度缺失使"工具重名"结论不可全信。

### 3.2 预测基于什么？
- 现状：知识库模式（6 条，绑 rc.6）+ 运行时验证（directory-picker 机制、runtimeProbe 服务存在性）+ 未校准分数。
- **审视指出**：harness 自带的 E6 事件流（`tool/call`/`tool/result`/`turn/end`）就是校准数据源——
  可以统计"某插件加载失败率"、"工具调用失败率"、"组合变更后的行为漂移"。
  一个面向本质需求的预测器应当：先收集基线行为（事件统计），再对新组合做**对照预测**（变更前后事件分布差异），
  而不是只输出静态信号清单。"无事故数据"的辩解不成立——**事件流就是事故/行为数据**，只是没接。
- 结论：预测=启发式+观点（已诚实标注），但**本可校准而未校准**，这是本质差距不是表述差距。

### 3.3 冲突检测可靠吗？
- 可靠部分：重名拒绝语义方向正确（E1/E2 实证）；行覆盖/禁用语义正确（patch 契约）；版本范围满足用自研 semver（部分版本号已修，22/22）。
- 不可靠部分：
  1. **作用域盲区**（E3）：不区分 agent 作用域 → 同名结论方向性风险。
  2. 静态扫描覆盖有限：字面量 name 之外（变量/模板/动态注册）漏检——已标 static-suspect + 动态 hint，但未给出"漏检概率"。
  3. 不执行 harness 注册逻辑：dump-config 只给组合树，不给注册行为；"疑似"与"harness 实际拒绝"的鸿沟只靠声明，没有桥接工具（如 loader 试挂载）。
  4. 服务提供者：名称推断（近似），非运行期注册表查询（runtimeProbe 只探存在性，不探注册内容）。
- 净判断：**合格 linter，非仲裁者**——与第三版结论一致，但本版补上了"作用域"这个第三版也漏掉的契约维度。

## 5. 结论与优先级（审视者版）

一句话：**整改后它是"真相层可信、声明层诚实、但契约层缺作用域、校准层缺数据消费"的组合 linter**；
比整改前显著进步（不再自封预言机），但离"权威判定者"还差两个本质维度。

**P0（本质，决定结论方向）**：
1. **作用域感知的冲突判定**：工具/命令/服务注册按作用域（全局 vs agent.ctx）分区判定；全局同名=contract 硬错，
   agent 作用域同名=合法（供 preset/agent 变体）。证据：E3。这直接修正 tool-collision 的方向性风险。
2. **事件流校准接入**：`tool/call`+`tool/result`+`turn/end` 统计基线（失败率/调用分布），
   预测输出附带"与基线对照"的实测支撑；无基线时维持未校准声明。证据：E6。

**P1（契约实证）**：
3. 实证 `provide` 重复语义（同 scope 二次 provide：拒绝或覆盖）——评审"后胜"论断待验证（E4 线索），
   验证后校准 service-collision 的 impact 文本。
4. 泄漏扫描按 apply 路径切片（而非全包计数），降低虚警。

**P2（工程）**：semver/CI/路径（已完）+ 补冲突"疑似 vs 确认"的桥接（如 loader 试挂载工具）。

**对评审本身的审视**：第三版框架（R0–R5）方向正确，但两处需证据校准：
"服务覆盖=后胜"无源码实证（待验）；"无事故数据"不成立（E6 事件流即行为数据）。
这正说明：**评审与项目一样，都要接受标准真相的检验。**
